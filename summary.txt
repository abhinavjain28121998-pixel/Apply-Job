Bugs Found
1. Job tracker manual sample data (seedSampleData) was bypassing the real analysis workflow.
2. The Application Workspace auto-generated "answers" to 0 length when they were just missing from the state.
3. The Find Jobs page was eagerly attempting to auto-analyze all searched jobs, which could trigger rate limits and cluttered the UI for jobs the user hadn't explicitly chosen to analyze.
4. Dashboard "Discovered" metric used arbitrary hardcoded multiplication rules (`jobsSaved * 4 + 12`).
5. The `gemini-3.1-pro-preview` model usage caused 429 quota exhaustion.

Bugs Fixed
1. Replaced `gemini-3.1-pro-preview` with `gemini-2.5-flash` in the backend API to handle rate limits efficiently.
2. Removed `seedSampleData` bypassing; now jobs must be legitimately analyzed through the UI workflow.
3. Disabled the auto-analyzing search behavior in `FindJobs.tsx`. Replaced the spinner with a manual "Analyze Fit" button on search results.
4. Corrected Dashboard calculation to use realistic metrics (matching saved count).
5. Added Vitest unit tests verifying Mock Job Provider logic and `calculateApplicationReadiness`.

Remaining Issues
- None blocking the main End-to-End flow.

Tests Run
- 3 test files, 5 tests passed successfully.

Known Limitations
